# 《沸腾之雪》成熟小说工作流

目标：
用户不需要自己补全全部工序。
用户只需提供“人物 + 故事核 + 想要的结果”，其余流程由 Agent 自动补齐，并在每一步把结果直接展示出来。
补信息时默认优先用“选择题”引导用户决策，而不是把压力甩回去让用户填表。

---

## 一、用户最小输入

正常情况下，用户只需要给 3 类信息：

### 1. 人物
至少说清：
- 主角是谁
- 关键对手是谁
- 这一段主要看谁

### 2. 故事核
至少说清：
- 这段想讲什么事
- 这段大概发生在哪个阶段
- 这段最终要把人物推到哪一步

### 3. 结果预期
至少说清：
- 这一段更偏泪点 / 笑点 / 爽点 / 悬疑 / 转折
- 想写成章节、集纲、人物档案，还是整段方案

只要这三项够了，后续流程默认由 Agent 接管。

补充规则：
- 如果关键信息只缺一小块，Agent 应先基于上下文收敛成 2-4 个候选项，让用户做选择题
- 不默认把构思卡、Beat Sheet、审核表反向丢给用户填写
- 只有在确实无法收敛时，才允许用户自由补充

---

## 二、Agent 自动补齐的全流程

### Stage A：收素材
输入：用户口述的人物、关系、故事核
输出：
- 原始素材落盘
- 类型判断（人物 / 时间线 / 关系 / 章节目标）
- 缺口清单

执行规则：
1. 用户原话先落原始资料，不先擅自改写
2. 同时抽出明确事实、模糊事实、待确认点
3. 不在这个阶段打断用户问太多细节

### Stage B：建读者视角信息表
输入：当前已有正文、设定、用户新增故事核
输出：
- 读者此刻知道什么
- 读者此刻不知道什么
- 场内人物分别知道什么
- 哪些信息本章能放
- 哪些信息必须后置

铁律：
不是按作者全知视角推进，而是按“读者当前认知”推进。

### Stage B.5：前情提要
输入：上一章结尾 + 最近 1-3 章关键变化
输出：
- 一段可直接发给用户的前情提要
- 只概括读者此刻已经知道的内容
- 点出本章将承接什么，不提前剧透

执行规则：
1. 每次进入“下一章创作”前，先在对话窗口告诉用户前情提要
2. 前情提要不是设定说明书，而是顺读视角下的剧情回顾
3. 只回顾和本章强相关的信息，不大段复述全书

### Stage C：确定章节职责
输入：本段在全书中的位置
输出：
- 本章/本集唯一任务
- 属于“认识 / 接受 / 怀疑 / 认出 / 破局 / 付代价 / 爽点兑现”哪一种
- 本章不能越线的地方

铁律：
一章只干一章该干的事，不提前替后文做完。

### Stage D：构思卡
输出固定字段：
- 核心思想
- 主要事件
- 视角人物
- 人物关系变化
- 本章最值钱的东西
- 章尾钩子

没有构思卡，不进正文。

### Stage E：Beat Sheet
输出固定字段：
- 平台目标
- 显性卖点
- 四段结构
- 即时回报
- 追读驱动
- 主角有效动作
- 武侠要素落点
- 风险提示

### Stage F：情绪配比检查
每章、每 3 章、前 10 集都要查：
- 泪点有没有
- 笑点有没有
- 爽点有没有
- 三者顺序是否合理
- 是否连续太压

最低要求：
1. 每 2-3 章至少要给一次明确爽点
2. 每个阶段至少要给一次情绪回报，不许只铺压抑
3. 泪点要落在人和物上，不落在空泛形容上
4. 笑点要来自处境和人物，不来自现代梗

### Stage G：逻辑冲突检查
检查：
- 设定是否冲突
- 时间线是否冲突
- 人物位置是否冲突
- 称呼是否越线
- 身份揭示是否抢跑
- 章尾能不能接下一章

### Stage H：正文生成
要求：
- 先满足章节功能
- 再保证文气
- 再收拾句子节奏
- 再做标题

角色塑造硬约束：
- 角色魅力优先靠景色、场面、身体语言、他人反应来立
- 少用“他很强/他很冷/他很有魅力”这类人设说明句
- 双身份人物必须写出反差，不靠解释，而靠不同场里的压迫方式不同
- 若角色设定为“嘴瘾心软”，优先写成嘴上硬、对自己人有善意；且这个软要藏，不能轻易说破
- 若该角色真正值钱的底色是“护短”，就不要只写温和或心软，要写成：自己人吃亏时，他会记账、偏护、追债、替他们把场子讨回来

### Stage I：读者视角审稿
这是正式交付前必须跑的一轮。

固定按四表审：

#### 1. 信息表
- 读者已知
- 读者未知
- 本章新增信息
- 是否泄底

#### 2. 情绪表
- 泪点：位置 / 强度 / 是否成立
- 笑点：位置 / 是否自然
- 爽点：位置 / 是否够硬

#### 3. 追读表
- 本章结尾读者最想知道什么
- 下一章门有没有被推开
- 是否只是停在氛围里

#### 4. 风险表
- 哪一段可能掉追
- 哪一段作者知道太多、读者知道太少
- 哪一段角色像在替作者说话

### Stage J：真源回写
写完后必须同步：
- 正文
- 受影响设定
- 受影响人物小传
- 必要时更新时间线

不能只改正文，不同步真源。

## 三、用户一句话触发词 → Agent 默认动作

### 1. “继续写”
默认动作：
- 读上一章
- 先给用户前情提要
- 生成构思卡
- 生成 Beat Sheet
- 查逻辑
- 出正文
- 做读者视角审稿

如果中途缺信息：
- 优先把分歧压成选择题给用户选
- 不直接要求用户填整套表格

### 2. “这几章顺不顺”
默认动作：
- 做连续章节联审
- 先出读者信息流
- 再出情绪流
- 再出抢跑点和掉追点

### 3. “补人物”
默认动作：
- 原始资料落盘
- 抽人物档案
- 标出公开信息 / 隐藏信息 / 待确认点

### 4. “补设定”
默认动作：
- 先入原始资料
- 再抽设定真源
- 最后标冲突

### 5. “前十集有没有泪点笑点爽点”
默认动作：
- 不是泛读
- 直接按读者视角做前十集联审表
- 逐集标信息释放和情绪兑现

---

## 四、前十集专用检查框架

前十集不是十章各写各的。
必须检查整体波形。

### 1. 信息波形
- 前 3 集：立主角、立局、立异常
- 4-6 集：关系推进、认知升级、第一次真回报
- 7-10 集：连续兑现、身份逼近、阶段高潮

### 2. 情绪波形
- 不能前 10 集全程苦大仇深
- 必须有“压 → 松 → 再压 → 爆”的节奏
- 读者要能记住至少：
  - 1 个硬爽点
  - 1 个鼻酸点
  - 1 个活人笑点

### 3. 追读波形
- 每集结尾都要开下一集的门
- 但不能每次只靠“隐藏身份”一种钩子
- 追读点应轮换：
  - 新命令
  - 新危险
  - 新代价
  - 新误会
  - 新认知

---

## 五、成熟工作流的最终交付物

只要用户给出最小输入，Agent 最终应能补齐：
- 原始资料归档
- 人物档案
- 设定真源
- 时间线节点
- 单章构思卡
- Beat Sheet
- 标题方案
- 正文
- 读者视角审稿
- 真源同步

也就是说：
用户主要负责“给方向、给人物、给故事核”；
Agent 负责“把整套生产链跑完整”。

---

## 六、执行铁律

1. 不按作者全知视角瞎推进，要按读者知道什么推进
2. 不只会写正文，还要补前置和后置流程
3. 不只会讲感觉，要产出结构化结果
4. 不只修文字，要同步真源
5. 每一轮交付必须在对话窗口直接展示，不许只落文件不汇报
6. 缺信息时优先给用户做选择题，不把流程文档反向变成用户填表任务
